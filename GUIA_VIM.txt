1. CONFIGURACIÓN BÁSICA
============================================================

- Tecla líder: ESPACIO (la usas antes de casi todos los atajos,
  p. ej. <space>w = guardar)
- Números de línea: absoluto + relativo
- Tabulación: 4 espacios (expandtab)
- Portapapeles: conectado al del sistema (unnamedplus)
- Deshacer: PERSISTENTE entre sesiones (guarda en ~/.vim/undo/)
- Sin archivos de respaldo ni swap (se confía en git)
- Cursor y búsquedas: se mantiene contexto (scrolloff=8)

3. ATAJOS GENERALES
============================================================

  <space>w        Guardar archivo
  <space>q        Cerrar ventana
  jj              Salir de modo insertar (como Esc)
  <space><space>  Saltar al buffer anterior (<C-^>)
  <S-l>           Siguiente buffer
  <S-h>           Buffer anterior
  <space>bd       Cerrar buffer actual
  <space>sv       Dividir pantalla vertical
  <space>sh       Dividir pantalla horizontal
  <C-h> <C-j> <C-k> <C-l>  Moverte entre ventanas
  <space>t        Abrir una terminal (:term)
  <space>m        Compilar de forma asíncrona (:Make)
  <space>u        Árbol de deshacer (undotree)
  <space>l        Quitar el resaltado de búsqueda
  <space>h        Insertar cabecera de 42 (Stdheader)

  NOTA: <C-h/j/k/l> es solo de Vim. La integración con los
  paneles de tmux la hace la config de Neovim (Navigator.nvim),
  que además sabe saltar a Vim si hay una sesión vim abierta.

============================================================
5. GIT (fugitive + gitgutter)
============================================================

  <space>gg       Panel de estado de git (:Git)
  <space>gd       Diff del buffer contra el índice (:Gvdiffsplit)
  <space>gg luego:
    cc            Hacer commit (escribe el mensaje y :wq)
    dp / do       Difusiones hacia/desde el otro lado del diff
    dv            Diff vertical

  GITGUTTER (columna con marcas):
    ]c            Siguiente cambio
    [c            Cambio anterior
    <leader>hp     Previsualizar el cambio del bloque (hunk)
    <leader>hs     Añadir el bloque al índice (stage)
    <leader>hu     Volver atrás un bloque (undo hunk)

  CONSEJO: gitgutter actualiza con reposo del editor (updatetime).

6. SÍMBOLOS C/C++: CSCOPE + GTAGS  <-- LO NUEVO
============================================================

Esto ES la gran ventaja de Vim frente a Neovim en tu setup:
búsqueda de símbolos SIN servidor LSP, usando ctags + gtags.

CÓMO FUNCIONA
  - vim-gutentags detecta la raíz del proyecto (.root, .git, ...)
  - En segundo plano genera .tags (ctags) y la base GTAGS
  - gutentags_plus convierte :GscopeFind en búsquedas sobre GTAGS
  - Los resultados van al QUICKFIX (ventana inferior), y salta
    automáticamente al resultado bajo el cursor.

ATAJOS (con el cursor SOBRE el símbolo):
  <space>gs      Encontrar el SÍMBOLO (C symbol) bajo el cursor
  <space>gD      Ir a la DEFINICIÓN del símbolo
  <space>gc      Funciones que LLAMAN a este símbolo (callers)
  <space>gB      Funciones a las que LLAMA (llamadas dentro del símbolo)
  <space>gt      Buscar TEXTO (la palabra bajo el cursor)
  <space>ge      Buscar por PATRÓN (egrep)
  <space>gf      Buscar el ARCHIVO bajo el cursor (:GscopeFind f)
  <space>gi      Archivos que INCLUYEN al archivo bajo el cursor
  <space>ga      Dónde se ASIGNA un valor a la variable
  <space>gz      Llamadas a la función bajo el cursor

NAVEGACIÓN EN RESULTADOS (quickfix):
  :cn  / :cp       Resultado siguiente / anterior
  :copen           Abrir la lista de resultados
  :cclose          Cerrarla
  <space>gg / gd   OJO: están tomados por Git; por eso
    la definición es <space>gD y los callers <space>gB.

QUÉ NECESITAS INSTALADO (ver sección 11):
  universal-ctags  y  global (GTAGS). Sin ellos,
  gutentags no genera bases y los atajos no responden.

7. EDICIÓN RÁPIDA
============================================================

  Comentarios:
    gcc              Comentar/descomentar la línea
    gc               (en Visual) comentar la selección
    gb               Comentar en bloque (Visual)

  Surround (envolver):
    ysiw"            Envolver la palabra con comillas
    cs"'             Cambiar " por ' (con cambiar envoltura)
    ds"              Borrar las comillas alrededor

  Targets.vim (text objects extra):
    di' / da'       Borrar dentro / incluyendo comillas simples
    di" / da"       Ídem con comillas dobles
    ci( / ci)       Cambiar el contenido del paréntesis
    ya)             Copiar el contenido y el paréntesis
    ia / aa         Argumento (dentro / incluyendo comas)
    i/ / a/         Dentro / alrededor de la función
    it o i<         Dentro de una etiqueta HTML (.vim ftplugin)

  Multi-cursor (vim-visual-multi):
    Ctrl+n           Seleccionar la palabra actual y añadir cursores
    n                Siguiente coincidencia (añadir cursor)
    q                Dejar de añadir
    [ / ]            Saltar entre cursores

  Otros:
    *                Resalta y salta a la siguiente coincidencia
                     de la palabra bajo el cursor (sin mover el cursor)
    v J / v K        Mover líneas seleccionadas arriba/abajo
    .                Repetir el último cambio (vim-repeat lo extiende)

11. DEPENDENCIAS EXTERNAS Y GENERACIÓN DE SÍMBOLOS
============================================================

Instalar una vez (gestor de paquetes del SO):
  universal-ctags   -> sustituye a exuberant-ctags (el viejo)
                       genera el fichero .tags con la indexación
                       de funciones, variables, estructuras...
  global            -> genera las bases GTAGS/GRTAGS/GPATH
                       que usa :GscopeFind

En Debian/Ubuntu:
  sudo apt install universal-ctags global

O en macOS:
  brew install universal-ctags global

FLUJO DE TRABAJO:
  1. Abres un archivo de un proyecto con raíz (.git o .root)
  2. gutentags detecta la raíz y, en silencio, genera .tags y GTAGS
  3. Te pones sobre un símbolo (p. ej. una función) y pulsas <space>gs
  4. El primer golpe puede tardar un poco (está indexando);
     los siguientes son instantáneos.

NOTA: si cambias la base de cscope a mano, borra el directorio
  ~/.cache/vim/ctags/ y vuelve a generar; las bases se cachean ahí.

12. DIFERENCIAS CLAVE CON NEOVIM
============================================================

  ┌──────────────┬────────────────────────┬─────────────────────┐
  │              │ VIM (este fichero)     │ NEOVIM (GUIA_NVIM)  │
  ├──────────────┼────────────────────────┼─────────────────────┤
  │ Plugin       │ vim-plug (Plug)        │ Lazy.nvim (Lua)     │
  │ Símbolos     │ cscope/gtags externos  │ LSP (clangd, etc.)  │
  │ Búsqueda     │ FZF (:Rg)              │ Telescope           │
  │ Tree de arch│ NERDTree                 │ Neo-tree            │
  │ Sesiones     │ (no automático)        │ persistence.nvim    │
  │ Text objects│ targets.vim             │ + treesitter-textobjects│
  │ Status line │ airline                │ lualine + bufferline │
  │ Terminal     │ :term manual focus     │ Navigator.nvim (tmux)│
  └──────────────┴────────────────────────┴─────────────────────┘

  REGLA DE ORO:
    - Vim    = ligero, símbolos con ctags/gtags, sin LSP.
      Ideal para editar rápido un archivo o proyectos enormes.
    - Neovim = potente, con LSP (definición, refactor), Telescope.
      Ideal para el día a día de desarrollo.
